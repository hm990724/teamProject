# 콕콕 (KokKok) · 맞춤형 의료 서비스

> 몸 그림에서 아픈 부위를 콕 누르고 증상을 적으면, **관련 질환 후보 · 추천 진료과 · 질환 통계 · 가까운 병원**까지 이어서 안내해 주는 증상 가이드 웹 서비스입니다.
> 공공데이터(건강보험심사평가원)와 생성형 AI(Gemini)를 결합했고, 진단이 아닌 **진료과·병원을 찾기 위한 참고용 안내**를 목표로 합니다.

## 주요 기능

### 1. 인터랙티브 인체 부위 선택
- 앞면/뒷면을 전환하며 부위를 선택하는 **커스텀 Streamlit 컴포넌트**(`body_map/index.html`)
- 머리·목·어깨·가슴·팔·손·배·옆구리·골반·엉덩이·등·허리·허벅지·종아리·전신 등 **15개 부위**
- 부위별로 상병 분류(ICD) 계열과 기본 진료과를 매핑

### 2. 증상 입력 및 AI 종합 소견
- 자유 서술 증상 + 나이·성별(선택) + 불편한 정도(4단계) 입력
- Gemini가 증상 표현을 근거로 **종합 소견 · 추천 진료과 · 질환명 키워드 · 생활 안내**를 JSON으로 생성

### 3. 관련 질환 후보 랭킹
- 심평원 상병(질병) 목록에서 후보를 추린 뒤, AI가 **목록 안에서만** 최대 6개를 가능성 순으로 선택
- 각 후보에 가능성(높음/중간/낮음), AI 코멘트, 일치한 키워드 칩 표시
- "이 결과가 나온 과정" 패널로 후보 풀 → 키워드 → 점수 → 나이·성별 반영 → 최종 선택 단계를 투명하게 공개

### 4. 질환 통계 대시보드
- 심평원 질병정보서비스 OpenAPI 기반 4종 통계 (탭 전환)
  - 성별·연령별 / 입원·외래별 / 요양기관 종별 / 요양기관 지역별
- 입력한 나이·성별이 해당 질환 환자 분포에서 **몇 번째로 많은 구간인지** 비교
- 외부 차트 라이브러리 없이 HTML/CSS로 직접 구현한 막대·세로 막대·도넛·누적 막대 차트
- 위키백과 요약을 함께 보여주는 질환 개요

### 5. 응급 징후 안내
- "의식을 잃", "경련", "호흡곤란", "식은땀" 등 **위험 키워드 규칙 탐지**(부정 표현 처리 포함) + AI 판단 결합
- 응급 가능성이 있으면 119/응급실 안내 배너를 최우선 노출

### 6. 병원 찾기 연계
- 선택한 질환·추천 진료과를 세션으로 넘겨 병원 찾기 페이지(`pages/2_hospital_finder.py`)로 이동
- 영업 상태 배지, 요일별 진료시간 막대 등 병원 정보용 UI 컴포넌트 제공

### 7. 기타
- 질환명 직접 검색 (두 글자 이상, 부위 무관 전체 검색)
- 알림(벨) 팝오버, 토스트, 데모 로그인 계정 UI
- 로딩 스켈레톤, 진입 애니메이션, 모바일 반응형 레이아웃

## 핵심 설계 포인트

### 🛡️ AI 환각 방지: "후보 풀 안에서만 고르게 하기"
LLM이 병명을 자유롭게 생성하면 존재하지 않는 질환이나 잘못된 코드를 만들 수 있어, 구조를 다음과 같이 나눴습니다.

1. 부위별 ICD 계열로 심평원 상병 목록을 조회해 **후보 풀** 구성
2. AI가 제안한 키워드 + 사용자가 쓴 단어로 질환명에 **희소 단어일수록 높은 가중치**(역문서빈도 방식)를 줘 후보 40건 추림
3. 후보 목록(`상병코드|질환명|환자 분포`)만 프롬프트에 넣고 "목록 밖 질환은 절대 쓰지 말 것"을 지시
4. 응답의 상병코드가 **후보 목록에 실제로 존재하는지 코드로 재검증**하고, 중복·범위 밖 코드는 폐기
5. 가능성 값도 허용 값(높음/중간/낮음) 외에는 비워 둠

### 🚨 응급 판단은 규칙 + AI 이중 장치
- 위험 표현 사전 + **부정어 처리**("의식은 있고 경련은 없어요" 등 오탐 방지)
- AI의 `emergency`는 기본값 false, **근거 문구가 있고 불편 정도가 높을 때만** 인정
- 감기·미열·만성 증상은 응급으로 분류하지 않도록 프롬프트에 명시

### 🔌 불안정한 공공 API 대응
- 서비스/오퍼레이션 이름 변형 후보와 https/http를 순차 시도하고, 성공한 조합은 기억(`_OK`)
- 일시 오류(5xx, 인증 지연 코드)에 한해 **점진적 백오프 재시도**, 그 외 오류는 즉시 예외 처리
- JSON/XML 응답을 모두 파싱하고 게이트웨이 오류 메시지를 사람이 읽을 수 있게 변환
- 통계는 직전 연도 → 전전년도 순으로 폴백, `st.cache_data`로 6~24시간 캐시

### ⚡ Gemini 모델 자동 탐색과 응답 속도
- 모델 목록 API에서 `generateContent` 지원 **flash 계열만 필터링**하고 최신 버전 순 정렬
- 타임아웃·연결 실패·404 시 **다음 모델로 자동 폴백**(최대 8개), 오류 힌트에 있는 대체 모델 우선 시도
- 2.5 계열은 `thinkingBudget: 0`으로 응답 지연 단축
- 질환별 통계 조회는 `ThreadPoolExecutor`로 병렬 처리, 단계별 소요 시간 로깅

### ✅ 통계 데이터 신뢰도 표시
- 응답 스키마가 API마다 달라 컬럼을 정규식으로 분류(환자 수·진료비·일수 등)하고 한글 라벨로 변환
- "계" 행과 세부 구간 합계를 비교해 **오차 0.5% 이하면 '합계 일치'**, 아니면 경고 배지 표시
- 환자 수는 인구 대비 비율이 아님을 화면에 명시

### 🧭 설명 가능한 결과
- 후보 풀 크기, 사용 키워드 수, 추린 후보 수, 환자 분포 반영 수를 KPI로 보여주고
- AI 판단 영역과 사람이 정한 규칙(부위→분류 매핑) 영역을 구분해서 안내

## 실행 방법

```bash
# 1. 저장소 클론
git clone https://github.com/hm990724/teamProject.git
cd teamProject

# 2. 가상환경 (선택) 및 패키지 설치
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. 환경 변수 설정 (아래 참고)
cp .env.example .env             # 없다면 직접 .env 파일 생성

# 4. 실행
streamlit run main.py
```

> 인체 부위 컴포넌트는 `body_map/index.html`을 사용하므로 폴더 구조를 그대로 유지해야 합니다.

## 환경 변수

프로젝트 루트에 `.env` 파일을 만들어 아래 값을 설정합니다.

```env
HIRA_DISEASE_SERVICE_KEY=공공데이터포털에서 발급받은 심평원 질병정보서비스 인증키
GEMINI_API_KEY=Google AI Studio에서 발급받은 API 키
# GEMINI_MODEL=선택 사항: 우선 사용할 모델명 (미지정 시 자동 탐색)
```

- 공공데이터포털: https://www.data.go.kr (건강보험심사평가원 질병정보서비스 활용 신청)
- Gemini API 키가 없으면 AI 소견은 생략되고 **키워드 점수 순서**로만 후보를 보여줍니다.
- 병원 찾기 화면에서 사용하는 추가 API 키가 있다면 같은 `.env`에 함께 설정하세요.

## 주의사항

- 본 서비스는 **진단이 아니라 진료과와 병원을 찾기 위한 참고용 안내**입니다.
- 질환 후보는 입력한 설명과 나이·성별을 바탕으로 한 추정이며, 의학적 정확도를 별도로 검증하지 않았습니다.
- 통계는 건강보험 청구 자료(주상병 기준)라 치료 결과·완치 여부는 포함하지 않습니다.
- 증상이 계속되거나 심해지면 반드시 의료진과 상담하세요. 응급이 의심되면 즉시 119에 연락하세요.
- 데이터 출처: 건강보험심사평가원 질병정보서비스, 위키백과
